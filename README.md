# 赫拉手帐 · HERA'S JOURNAL

一个**只保存在本地**的女性周期、情绪与身体手帐。记录身体，翻译疼痛，粉碎谣言。

没有账号，没有服务器，没有上传。所有记录留在你自己的浏览器里。

单文件应用，零依赖、零构建；当前版本 `0.10`，Service Worker 缓存版本 `v7`。

---

## 这是什么

赫拉手帐是一个**单文件 Web 应用**（`index.html`，零依赖、零构建）：用日历记录月经周期、复合情绪、疼痛与日记，再把这些零散的感受整理成**可以带去诊室的东西**。

它不评分、不打卡、不制造焦虑，也不替你做医学判断。数据不够时，它会直接说「还不够」，而不是编一个看起来很像的数字。

## 功能

### 记录

| 模块 | 说明 |
| --- | --- |
| 日历 | 经期开始 / 结束、疼痛 0–5 级、备注；跨月查看、回到今天；非经期但有症状记录的日子，格子右下角有一个小圆点（疼痛、情绪、睡眠、运动、性生活、分泌物、用药、体温、便便、其他不适） |
| 月经量 | 主面板三档：少 / 正常 / 多，单选，再点一次取消 |
| 复合情绪 | 同一天可选任意多个情绪（平静 / 委屈 / 暴躁 / 想被抱抱），多选时格子显示「首个 emoji + 加号」 |
| 更多记录（可选） | 睡眠、运动、用药、性生活（无 / 已避孕 / 未避孕）、分泌物（干燥 / 粘稠 / 蛋清状）、体温、便便（正常 / 腹泻 / 便秘）、其他不适（腰酸 / 乳房胀痛 / 头晕）；默认折叠，空着就不写入、不占存储 |
| 体温 | 文本框输入（移动端弹出小数键盘）：输入 `36.` 会在失焦时自动补成 `36.0`；只接受 34.0–43.0 ℃，越界轻提示并回退到上一次保存的值；**失焦时输入框为空只恢复原值，不会删除已保存的体温**——要清空体温请用「清空这几项」 |
| 「今天先不记」 | 当天不想记录时收起输入区，不产生任何数据，也不写一句负罪感文案 |
| 周期阶段带 | 月经期 / 卵泡期 / 排卵期 / 黄体期，颜色 + 文字双标注，今天用圆点标记 |
| 连续经期开始 | 当上一次经期还没有点「结束」时，再点「经期开始」会先确认「你上一条经期似乎没有点结束，是否要覆盖上一次的开始时间？」；取消则什么都不改，确认才会用新的开始日覆盖上一次的开始 |

### 看见

- **疼痛图表**：最近 30 天的疼痛与情绪折线。
- **诚实预测**：均值 + 标准差得出「预计 11 月 18–22 日（置信度：中）」的区间，而不是假装精确到某一天；完整周期不足 2 个、或标准差 > 7 天时完全停止预测并说明原因，绝不拿 28 天兜底。日历可一键关掉预测。
- **观察笔记**：累计 ≥ 3 个完整周期后，比较月经期 / 黄体期与其他阶段的疼痛、经前负面情绪频率，用「你记录到：……」的措辞呈现，只观察、不诊断，附一句「带着这个模式去和医生讨论，可能会有所帮助」。
- **身体自查**：按症状组合给出「什么时候该去医院」的分级提示。

### 带走

- **就诊备忘录**：把口述翻译成五段式（主诉 / 时间线 / 伴随症状 / 已尝试措施 / 关键问题）。
  - 翻译引擎只提取**动词与感官形容词**（针扎、拧着、往下拽、发木发胀……），不猜名词比喻；否定句会拦下（「不是针扎的那种刺痛」不会变成刺痛）。
  - 预览里的部位、性质、VAS、病程、药名、效果、口述时间都是**胶囊标签**，点一下就能换成同类医学术语，也可以删掉；改动即时同步到正文、复制文本、长图与 PDF。
  - 口述与打卡记录**并列展示**：一致时合并成一句，不一致时各写一行，不会用打卡覆盖你的说法。
  - 支持复制文本、导出长图、`打印 / 导出 PDF`（A4 灰度可读，页脚带「不构成诊断」声明）。
- **时空信件**：写给未来某一天自己的信，到解锁日才能打开。取消封存会明确说明这封信是否已写回本机；若解密保护处于开启状态，会提示「刷新后这封信可能重新出现」。
- **家属求生卡**：给陪在身边的人一张「现在能做什么」的说明卡，可下载为图片。
- **请假条**：四个角色（领导 / 老师或辅导员 / 导师 / 客户或合作方）、半天或数天、可填称呼，生成一条不卑不亢、带一句话交接的消息。
- **谣言粉碎 & 知识库**：17 条常见健康谣言 + 296 条本地百科条目，**16 个分类**（全部 + 15 类：经期护理、避孕用药、妇科疾病、日常防护、疫苗筛查、常见症状、经期与内分泌、妇科疾病与筛查、避孕与两性健康、心理与情绪内耗、生活避坑与智商税、身体求救信号、就医避坑、校园心理、病耻感破除），支持搜索、键盘操作与分类筛选。
- **夸夸机**：需要被夸一句的时候。

## 快速开始

1. 拿到整个文件夹（至少需要 `index.html`）。
2. 双击 `index.html`，用浏览器打开即可使用。

想安装成独立应用（PWA、可离线、有桌面图标）时，需要经由 `http(s)://` 或 `localhost` 访问：

```bash
# 任选其一，在项目目录里执行
python -m http.server 8080
# 或
npx serve .
```

浏览器打开 `http://localhost:8080/`，地址栏出现「安装」提示即可安装。

> 直接双击（`file://`）也能完整使用，只是浏览器不允许 `file://` 注册 Service Worker，因此没有 PWA 离线安装。

## 数据与隐私

### 默认：全部留在本机

- 记录写入 **IndexedDB**（数据库 `hera-journal`，仓库 `meta` / `records` / `letters` / `vault`）；浏览器不支持时依次降级到 `localStorage`、内存，并在顶部给出一条可关闭的提示条。
- 存储层统一为异步的 `Store`（`get / set / remove / keys / clear / ready`），业务代码不直接碰存储；加密开启后加解密在存储层自动完成。
- 空间不足时只清理本应用自己的旧备份元信息，绝不删除 `records` / `letters`；仍写不进去就降级为「仅本页有效」并提示立即导出。
- 数据键名保持 `heraJournal.v1`（整份状态）与 `heraLetters.v1`（时空信件）；导出的备份是标准 JSON，可自行检查。
- **应用代码不主动联网**：页面里没有任何 `fetch` / `XHR` / `WebSocket` / `sendBeacon`，百科内容全部内置；CSP 限定了唯一的外部来源为本机 `'self'`，Service Worker 也只缓存同源文件。
- 数据只在你的设备上：没有账号，没有云端同步，没有统计与埋点。

### 解密失败保护（0.10 新增）

如果加密记录中有某几条无法解开（例如本机密钥损坏、密文被外部改动、浏览器异常），应用**不会静默跳过它们，也不会用不完整的内存数据覆盖原始密文**：

- 打开时，解不开的记录 / 信件会保留原始密文，并记入失败清单；它们不会被画到界面上。
- 顶部会出现一条提示条：「有 N 条记录解密失败，为防丢失已保留原样，本次保存已中止。」首次出现时还会有一次弹窗说明。
- 在失败清单清空之前，**所有写入都会被中止**（保存状态显示「保存已中止 · 有记录无法解密」），以免用缺项状态覆盖掉还留在磁盘上的密文。提示条可以手动关掉，但保存仍然中止，直到失败清单清空。
- 关闭加密、开启加密、封存新信件、取消封存这些操作也会被拦截或给出明确原因，不会冒险改动存储。
- 浏览器在关闭 / 刷新页面时会屏蔽弹窗，所以「离开页面前的最后一次自动保存」只做静默拒绝——**看到顶部提示条时，请先处理它再继续记录**。
- 刷新页面后提示仍在。恢复有两条路，取决于密文本身是否还完整：
  1. **密文可恢复**：用主密码重新解锁、或恢复本机密钥，让原始记录重新可以打开；失败清单清空后提示自动消失，写入恢复。
  2. **密文已损坏**：先确认手里有备份，再用「数据安全 → 清空本机数据」（两步确认）清空后，从备份导入。注意在失败清单清空之前，**导入也会被中止**（会提示「记录已读入，但写入浏览器存储时遇到问题」），这是刻意的保护，不要误以为导入成功。

要诚实说明：如果密文本身已经损坏且没有备份，应用无法把内容凭空变回来；这时只能靠之前的导出文件。

### 托管平台说明

如果你把它放在 GitHub Pages 之类的静态托管上，**托管方可能记录基础访问日志**（IP、时间、User-Agent），这不在应用控制范围内。应用本身不发起任何网络请求，也不含统计、埋点或第三方脚本。

### 可选：给记录加一把锁

「数据安全」面板里可以开启**本地加密（实验性）**：

- 数据密钥 DEK 使用 AES-GCM 256，`extractable: false`，每条记录独立 12 字节 IV；
- DEK 被两把钥匙分别包裹：本机密钥（Device-KEK，存在 IndexedDB 的 `vault` 仓库）与主密码派生密钥（PBKDF2-SHA256，310000 次迭代 + 16 字节盐）；
- 日常打开靠本机密钥自动解锁，**不需要输入密码**；只有本机密钥丢失（清除了站点数据、换了浏览器配置）时才需要主密码；
- 主密码从不存储；DEK 从不写入任何存储介质；加密只作用于 `records` 与 `letters`，`meta` 与 `vault` 不加密；
- **开启前的备份护栏**：如果你已经有记录、却从未导出过备份，开启加密前会先拦一次，提示先去「导出我的数据」。也可以确认风险后直接开启。
- 面板里可「立即锁定」：清掉内存中的密钥，显示解锁层，但保留本机密钥以便下次自动解锁。
- 存在解不开的记录时，**开启与关闭加密都会被阻止**（开启会回滚到未加密状态），避免把不完整的数据重新包一层。

需要诚实告知的边界：

> 清除浏览器数据 = 本机密钥丢失；忘记主密码且本机密钥丢失 = 数据无法恢复。

另外：**导出与打印的文件是明文**，加密只保护浏览器里的存储。导出前会有一次「导出文件是明文，请妥善保管」的提示。

### 防窥模式（眼睛图标）

一键遮住首页文案、情绪标签、疼痛描述、日历详情、备忘录预览、请假条与信件弹窗、月经量与体温等敏感内容。

身体日记、用药与体温输入框只做**视觉遮罩**（字迹透明 + 遮罩层），不会改动你正在输入的内容，也不会破坏输入法；关闭后原文完整恢复。防窥期间备忘录标签菜单、请假条等入口一律不可用；加密未解锁时收到的多标签广播只刷新事件，不会把内容画到屏幕上。

### 多标签页

同一浏览器开多个标签时，保存会通过 `BroadcastChannel` 通知彼此刷新，并做了合并与防抖，避免互相覆盖；正在输入日记时会先合并字段、稍后再重绘，不会抢走你的光标。加密开启时只广播「有更新」事件，不广播任何记录内容；未解锁的标签页收到广播也不会写入或渲染。

## 最近更新（0.10 · SW v7）

这是一轮以「不丢数据」和「诚实输入」为重点的修复：

- **解密失败保护**：解不开的记录保留原始密文，保存整体中止，顶部提示条 + 首次弹窗；同时拦住关闭 / 开启加密、封存与取消封存等高风险操作。
- **体温输入**：从 `type="number"` 改为文本框（`inputmode="decimal"`），`36.` 自动补成 `36.0`；空输入失焦只恢复原值，不再删除已保存体温；越界仍回退上一次有效值。
- **日历圆点**：除疼痛 / 情绪 / 睡眠 / 运动 / 性生活 / 分泌物 / 用药外，体温、便便与其他不适也算「有症状的日子」。
- **百科分类**：补上「就医避坑」「校园心理」「病耻感破除」三个 tab，现在 16 个 tab 覆盖全部 296 条与 15 个分类。
- **移除冗余 `wiki-data.json`**：该文件与内置 296 条完全重复，已删除；`sw.js` 升到 v7，缓存清单移除它，静态资源统一 cache-first（导航仍 network-first），页面不再有任何 `fetch`。
- **导入合并**：同一天只在导入数据的 `updatedAt` **严格更新**时覆盖，时间相同保留本机；时空信件按 id 保留本机优先。
- **连续经期开始**：上一次经期未结束时再点「经期开始」，必须先确认才会覆盖（见「记录」表）。
- **文案与守卫**：保存状态会区分「已自动保存 / 保存失败 / 保存已中止」；取消封存与封存被拦时会给出具体原因；关闭 / 刷新页面时不再调用会被浏览器屏蔽的弹窗。

> 更新 Service Worker 后**刷新一次页面**才会用上 v7；旧的 v6 外壳会在激活时自动清理。

## 使用建议

- 经期只需标记「开始 / 结束」，其余交给日历自动着色；不确定的日子可以先不记。
- 描述疼痛用大白话即可（「像被绞肉机绞」「一阵一阵地发木发胀」），备忘录会翻译成结构化语言；翻错了可以直接点标签改词或删词。
- 想看趋势先攒 2–3 个完整周期；周期带、预测与观察笔记会随着记录变多慢慢长出来。
- 定期用「导出我的数据」存一份 JSON；换设备时用「导入数据」按日期合并，**同一天以更新时间较新者为准，时间相同保留本机**。
- 如果打算开启加密，**先导出一次备份**——这比记住密码更稳妥。
- 如果看到顶部出现「有 N 条记录解密失败」提示条：先不要再记录，优先用主密码解锁或恢复本机密钥，让原始记录重新可读；若密文已经损坏，先确认手里有备份，再按「解密失败保护」一节的步骤从备份恢复——**不要在没有备份时直接清空浏览器站点数据**。

## 开发说明

- 没有构建步骤：所有 HTML / CSS / JS 都在 `index.html` 内，只用浏览器原生 API，不引入任何第三方库；页面通过严格 CSP 限制外部来源。
- 存储层是异步封装（`Store`），并内置了 IndexedDB → `localStorage` → 内存的三级降级；配额不足时的淘汰策略只针对本应用的旧备份元信息。
- 加密相关的密钥生成、包裹与加解密都在 `Vault` 模块中，业务代码只与 `Store` 交互。`Vault` 会记录打开失败（`hasFailures` / `failureInfo`），`persist`、`persistTimeLetters`、`persistSyncFallback`、加密开关与时空信件封存都依赖它来阻止覆盖。
- 修改 `sw.js` 的缓存内容时请同步提升 `CACHE_VERSION`，否则旧外壳会被继续使用。
- 百科数据全部内置为 `medicalWiki` 数组；以后若要恢复外部更新能力，应让**相同问题覆盖内置条目**（而不是按 `q` 跳过），并同步更新 `sw.js` 的缓存清单与 CSP。
- 改完建议做一轮手测：写一条记录 → 刷新仍在 → 防窥开关 → 导出 / 导入 → 打印预览 → 加密开启 / 锁定 / 解锁 → 多标签同时打开 → 输入 `36.` 失焦 → 连续两天点「经期开始」→ 模拟一条解不开的密文（看到提示条且无法保存）。
